# 길동무 — 집 → 새 사무실(금천구 독산로85길 37) 보행·환승 안내

## 1. 핵심 요약
- 시각장애인이 겪는 3대 문제(출구 방향 / 하차 후 방향 / 도보 지나침)를 **"내 몸 기준 시계 방향 + 거리"** 음성·진동으로 해결하는 PWA(설치형 웹앱)임.
- 예: "정류장까지 50미터, 7시 방향(왼쪽 뒤)" → 출구에서 나와 **직진인지 유턴인지** 즉시 판별됨.
- 지하철 구간은 GPS 불가 → 역 카운트다운(버튼 1회 = 1개 역)으로 하차역 안내함.
- **외부 지도 서버 접근이 차단되어 출구·정류장 좌표는 미입력 상태임. 현장 1회 기록 후 사용 가능함.**

## 2. 문제 → 해결 대응
| 문제 | 해결 방식 |
|---|---|
| 출구로 나와 직진/유턴 판단 불가 | 좌표 + 나침반/걷는 방향으로 "N시 방향 M미터" 안내 |
| 버스 하차 후 진행방향/반대방향 혼동 | 하차 정류장 접근 3단계 알림(500m·150m·40m) → 하차 후 현재 몸 방향 기준 안내 |
| 목적지를 지나치거나 헤맴 | 도착 반경 판정, 지나침 감지("되돌아가야 함"), 경로 이탈 경고, 30m 이내 근접 비프음(정면=높은 음) |
| 정확한 정류장 위치 | 정류장 기둥 옆 좌표를 기록해 사용(정류장 번호 21350 등 표기 병행) |

## 3. 구성
- `engine.js` : 안내 엔진(방위·시계 방향·이탈·지나침·역 카운트·하차 알림). Node 테스트 가능
- `app.js`, `index.html` : 큰 버튼·고대비 UI, 음성(TTS)·진동·비프·알림·음성 명령·위치 공유
- `route.json` : 기본 경로 D(3호선 금호→2호선 교대→구로디지털단지역 6번 출구→버스, 카카오맵 기준), 대안 A·C
- `test/engine.test.js` : 엔진 단위 테스트 10건(통과)

## 4. 최초 1회 준비 (필수)
1. HTTPS 주소로 배포함(위치·센서·설치 기능은 HTTPS 필수). 예: GitHub Pages(저장소 Settings → Pages → 브랜치 선택 → `/docs`).
2. 폰에서 열어 **홈 화면에 추가**함. 위치·동작(방향) 권한 허용함.
3. 동행인(활동지원사·동료)과 실제 경로를 한 번 걸으며 **[현장 기록 모드]** 에서 지점마다 [여기 저장] 실행함.
   - 기록 대상(경로 D): 금호역 1번 출구 앞 / 구로디지털단지역 6번 출구 앞 / 구로디지털단지역(중) 정류장(21002) / 하차 정류장(문성초등학교.금천가족문화센터) / 사무실 입구
   - 횡단보도·꺾는 곳은 [지점 추가]로 삽입함.
   - 하늘이 트인 곳에서 8초 서서 저장함. **지점당 서로 다른 날·시간에 2~3회 기록**하면 중앙값으로 자동 보정됨(이상치에 강함).
   - 평균 오차 25m 초과 시 저장 거부, 15m 초과 시 재기록 권고, 이전 기록과 30m 넘게 어긋나면 경고함. 목록에 기록 횟수와 편차가 표시됨.
   - 3회 이상 기록하면 튀는 기록은 자동 제외됨.
4. 구로디지털단지역은 **6번 출구**로 확정됨. 금호역은 **1번 출구**(집에서 도보 749m, 16분)로 확정됨.
5. **역 수 검증 완료**: 카카오맵 기준 3호선 금호→교대 6개 역(13분), 2호선 교대→구로디지털단지 9개 역(21분)으로 일치함.
6. 기록 후 [경로 내보내기]로 JSON을 백업함.

## 5. 사용법
- 출구에서 나오면 **멈춰서 5~10초 대기** → "정류장까지 N미터, X시 방향" 확인 후 출발함.
- 시계 방향 읽는 법: 12시=정면, 3시=오른쪽 직각, 6시=뒤돌아 유턴, 9시=왼쪽 직각, 7시=왼쪽 뒤.
- 진동: 정방향 짧게 1회 / 왼쪽 짧게 3회 / 오른쪽 짧게 5회 / 유턴 길게 3회 / 도착 길게 1회 / 경고 강하게 3회.
- 화면 어디든 누르면 마지막 안내 재생. [다음 ▶]은 도보=지점 건너뜀, 지하철=역 도착 확인, 버스=하차 후 다음 단계임.
- 폰은 화면이 위로 가게 수평 또는 가슴 앞에 세워 들기. 걷기 시작하면 GPS 걷는 방향으로 자동 보정됨.

## 6. 워치 연동
- 설정의 **알림 미러링**을 켜면 안내 문구가 폰 알림으로 발송되어 갤럭시 워치·Wear OS·Apple Watch에 진동과 함께 표시됨(워치 알림 미러링 설정 필요).
- 워치 단독 앱(Wear OS Kotlin / watchOS)은 2단계 과제임. 현재는 폰 앱이 안내하고 워치는 알림·진동 보조 수단임.

## 7. 한계 및 리스크
| 리스크 | 영향 | 대응 |
|---|---|---|
| 도심 GPS 오차 5~20m | 횡단보도·출구 구분 어려움 | 반경 자동 확대, 지점 촘촘히 기록, 횡단은 소리·지팡이로 확인 |
| 지하·승강장 GPS 불가 | 자동 안내 불가 | 역 카운트 버튼, 승강장 방면 안내방송 확인 |
| 폰 나침반 간섭 | 방향 오차 | 걷는 방향(GPS) 우선 사용, 정지 시에만 나침반 사용 |
| 실시간 버스 도착 정보 없음 | 탑승 버스 확인 불가 | 정류장 도착 정보는 카카오맵·기사 확인 병행(공공 API 키 확보 시 2단계에서 연동) |
| 좌표 오기록 | 잘못된 안내 | 기록 시 동행인 확인, 첫 2~3회는 동행 보행으로 검증 |

본 도구는 흰지팡이·안내견·주변 소리 확인을 **대체하지 않는 보조 수단**임.

## 9. 위치 보정 알고리즘 (engine.js)
| 단계 | 방식 | 효과 |
|---|---|---|
| 1회 기록(8초) | 기하 중앙값(Weiszfeld) + MAD 이상치 제거 → 1/오차² 가중 평균 | 순간적으로 튀는 값 제거, 정확한 측정에 큰 비중 |
| 여러 번 기록 | 위 방식으로 기록 간 융합. 추정 오차 = 1/√Σ(1/오차²), 하한 3m | 날·시간별 치우침 감소, 이상치 기록 자동 제외 |
| 보행 중 | 칼만 필터(위치+속도 등속 모델, 측정잡음=오차², 가속도 1.2m/s²) | 도착·방향 판정 떨림 감소, 걷는 방향·속도 보강 |

- 삼각측량은 기지국·Wi-Fi 등 기준점까지의 거리를 직접 재야 하는데 웹앱은 그 값에 접근할 수 없음. 폰 운영체제가 이미 결합한 위치를 사용함.
- 한계: 같은 순간·같은 장소의 GPS 오차는 서로 닮아 있어 8초 평균으로는 줄어들지 않음. 그래서 한 번의 기록 오차는 줄이지 않고 **여러 날 기록**을 융합할 때만 불확도를 줄임.

## 10. 학습 보행 (이용자 혼자 걸으며 자동 기록) — 동행인 불필요
- 앱의 **[🚶 직접 걸으며 자동 기록]** 을 누르고 평소처럼 걷기만 하면 좌표와 방향·거리가 자동 저장됨. 별도 조작 없음.
- 시작 위치 선택: 처음부터(집) 또는 특정 단계부터(예: 구로디지털단지역 출구부터 걸을 때).

| 기록 대상 | 자동 감지 방법 |
|---|---|
| 집 | 시작 후 서 있는 위치(양호한 측정 5회 중 오차 최소) |
| 지하철 입구 | 지하로 내려가 GPS가 25초 이상 끊길 때, 끊기기 직전 위치 |
| 지하철 출구 | 지상 복귀 후 보행 속도가 8초 지속되는 첫 위치. 열차 속도 구간은 무시 |
| 버스 정류장 | 안내된 도보거리의 60% 이상 걸은 뒤 20초 이상 정지한 위치. 신호 대기는 제외 |
| 하차 정류장 | 버스 주행 후 보행 속도로 바뀌는 위치(마지막 주행 시점 기준), 탑승 후 150m 이상 이동 시 |
| 사무실 | 안내된 도보거리의 60% 이상 걸은 뒤 12초 이상 정지한 위치 |
| 방향·거리·꺾는 곳 | 걸은 궤적을 평활화·단순화(RDP 8m) 후 구간별 방향과 거리, 35도 이상 꺾임을 지점으로 자동 삽입 |

- 결과 예: "처음에 북동쪽 방향으로 110미터, 오른쪽(약 90도)으로 꺾어 150미터 걸음. 총 약 260미터"
- 기록된 요약은 안내 시 단계 시작에 자동 낭독됨. [기록된 방향·거리 요약 듣기] 버튼으로 전체를 들을 수 있음.
- 여러 번 걸으면 기록이 자동 융합되어 정확도가 높아지고 꺾는 곳은 최신 보행으로 갱신됨.
- 한계: 신호 대기 중 정지, 버스 정체 서행, GPS 불량 구간에서는 오감지가 있을 수 있음. 감지 결과는 안내 중 계속 낭독되므로 이상하면 다시 걸어 덮어쓰기 바람.
- 검증: 가상 보행 데이터 테스트 5건 통과(`docs/test/learn.test.js`). **실제 보행 검증은 미실시.**
