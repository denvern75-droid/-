# 구글드라이브 방식 — PC 없이 24시간 (대안 C)

## 1. 핵심 요약

- 구글 서버(Apps Script)에서 실행되므로 **노트북·데스크탑 전원과 무관하게 동작함**
- 데스크탑이 구글드라이브에 보고서를 올려두기만 하면, 이후 모든 PC가 꺼져도 전송됨
- **봇에게 지시도 가능함** — 텔레그램에서 `/보고`, `/상태`, `/목록` 등을 입력하면 즉시 실행됨
- 노트북 24시간 가동이 불필요해짐 → 헤르메스 중계기 자체를 없앨 수 있음

> ⚠ 구글드라이브에 파일을 두는 것만으로는 안 됨. **Apps Script + 트리거**가 있어야 PC 없이 돌아감.
> 구글드라이브는 저장소일 뿐이고, 실행 주체는 Apps Script임.

## 2. 방식 비교

| 항목 | 현행 (헤르메스 노트북) | 구글드라이브 (본 방식) |
|---|---|---|
| 실행 주체 | 노트북 Windows 예약 작업 | 구글 서버 |
| PC 전원 의존 | **있음** — 노트북이 꺼지면 중단 | 없음 |
| 데스크탑 퇴근·외근 시 | 노트북이 대신 처리 | 무관 |
| 전송 주기 | 하루 1회(17:45) + 로그온 시 | **15분 주기**(조정 가능) |
| 봇 명령 수신 | 없음 | **있음** — 웹훅으로 즉시 응답 |
| 장애 지점 | Python 경로·절전·네트워크 | 구글 계정 권한·할당량 |
| 유지 비용 | 노트북 상시 전력·발열 | 없음 |

## 3. 설치 절차

### 3-1. 사전 준비

| 항목 | 확인 방법 |
|---|---|
| 봇 토큰 | 텔레그램 `@BotFather` → `/mybots` → API Token |
| chat_id | 봇에게 `/start` 발송 → 설치 후 `/아이디` 명령으로 확인 |
| 폴더 ID | 드라이브에서 감시할 폴더 열기 → 주소창 `folders/` 뒤 문자열 |

### 3-2. 스크립트 생성

1. `script.google.com` → **새 프로젝트**
2. 기본 `Code.gs` 내용을 지우고 저장소의 `gas/Code.gs` 내용을 붙여넣기
3. 좌측 파일 `+` → 스크립트 → 이름 `Commands` → `gas/Commands.gs` 내용 붙여넣기
4. 프로젝트 이름을 알아보기 쉽게 지정 (예: `업무보고 텔레그램 중계`)

### 3-3. 설정값 입력

프로젝트 설정 ⚙ → **스크립트 속성** → 아래 항목 추가

| 속성 | 값 | 필수 |
|---|---|---|
| `BOT_TOKEN` | BotFather 발급 토큰 | ✅ |
| `CHAT_ID` | 받을 대화방 ID | ✅ |
| `FOLDER_ID` | 감시할 드라이브 폴더 ID | ✅ |
| `EXTENSIONS` | `hwp,hwpx,docx,xlsx,pdf` (생략 시 기본값) | |
| `THREAD_ID` | 그룹 토픽 사용 시에만 | |
| `WEBHOOK_SECRET` | 임의 문자열 (봇 명령 사용 시) | 명령용 |
| `WEB_APP_URL` | 3-5에서 발급받는 `/exec` URL | 명령용 |

> 토큰은 스크립트 속성에만 두고, 코드에 직접 적지 않기 바람.

### 3-4. 보고 전송 켜기

편집기 상단 함수 선택 후 **실행**

| 순서 | 함수 | 확인 사항 |
|---|---|---|
| 1 | `doctor` | 실행 기록에서 `[실패]` 항목이 없어야 함 |
| 2 | `dryRun` | 전송 예정 목록이 의도와 맞는지 확인 |
| 3 | `runOnce` | 텔레그램에 실제 도착 확인 |
| 4 | `setup` | 15분 주기 트리거 설치 — **이 시점부터 PC 없이 동작함** |

최초 실행 시 구글 권한 승인 화면이 나옴 → **고급 → (프로젝트명)(으)로 이동 → 허용**

### 3-5. 봇 명령 켜기 (선택 — 지시·조회용)

1. 우측 상단 **배포 → 새 배포**
   - 유형: **웹 앱**
   - 실행 계정: **나**
   - 액세스 권한: **모든 사용자** ← 텔레그램 서버가 호출해야 하므로 필요함
2. 발급된 **`/exec` URL** 복사 → 스크립트 속성 `WEB_APP_URL` 에 저장
3. 스크립트 속성 `WEBHOOK_SECRET` 에 임의 문자열 저장
4. `setWebhook` 함수 실행
5. 텔레그램에서 `/도움` 입력 → 명령 목록이 오면 완료

> 코드를 고친 뒤에는 **배포 → 배포 관리 → 수정 → 버전: 새 버전**으로 다시 배포해야 반영됨.
> URL 은 그대로 유지되므로 웹훅을 다시 등록할 필요는 없음.

## 4. 봇 명령

| 명령 | 기능 |
|---|---|
| `/보고` `/report` | 지금 즉시 폴더를 확인해 새 보고를 전송함 |
| `/상태` `/status` | 설정·폴더·봇·트리거 진단(발송 없음) |
| `/목록` `/list` | 최근 24시간 대상 파일 목록(전송하지 않음) |
| `/시험` `/dryrun` | 전송 예정 목록만 확인 |
| `/재전송` `/resend` | 이력 초기화 후 최근 24시간 재전송 |
| `/아이디` `/id` | 이 대화방 chat_id 확인 |
| `/도움` `/help` | 명령 목록 |

**앞으로 다른 자동화를 붙일 때**는 `Commands.gs` 의 `COMMANDS` 배열에 항목만 추가하면 됨.

```javascript
{
  names: ['/주간계획', '/weekly'],
  desc: '주간업무계획 초안을 생성해 전송함',
  run: function (ctx) {
    // 여기에 처리 코드 작성
    return '주간계획 초안을 보냈음.';
  }
}
```

## 5. 보안

| 위협 | 대응 |
|---|---|
| 웹 앱 URL 노출 | URL 뒤 `?k=비밀키` 검증 — 불일치 시 무시함 |
| 비밀키까지 노출 | **CHAT_ID 일치 여부를 한 번 더 확인** — 등록된 대화방 외에는 명령 실행 불가 |
| 봇 토큰 노출 | 스크립트 속성에만 저장. 코드·저장소에 넣지 않음 |
| 권한 과다 | 드라이브는 **읽기 전용**(`drive.readonly`) 권한만 요청함 |

`액세스 권한: 모든 사용자`는 **URL을 아는 누구나 호출은 가능하다**는 뜻이며, 위 2중 검증 때문에 명령 실행은 불가함.

## 6. 리스크 요소

| 리스크 | 영향 | 대응 |
|---|---|---|
| 회사 보안정책상 Apps Script 제한 | 도입 불가 | 사전 확인 필요. 불가 시 대안 A/B 유지 |
| 데스크탑이 구글드라이브에 업로드하지 않음 | 파일이 도착하지 않음 | 구글 드라이브 데스크톱 동기화 설정 필요 |
| 실행 할당량 초과 | 일시 중단 | 개인 계정 기준 여유 있음. 트리거 주기를 늘려 조정 |
| 전송 지연 최대 15분 | 즉시성 저하 | `TRIGGER_MINUTES` 조정 또는 `/보고` 명령으로 즉시 실행 |
| 개인 구글 계정에 업무자료 경유 | 정보관리 규정 저촉 소지 | **업무용 계정 사용 권장. 기관 정보보안 담당 확인 필요함** |
| 파일 50MB 초과 | 첨부 불가 | 본문 + 드라이브 링크로 대체 전송함 |

## 7. 전환 판단

| 상황 | 권고 |
|---|---|
| Apps Script 사용 가능 + 업무용 구글 계정 있음 | **본 방식으로 전환하고 노트북 중계 중단** |
| 보안정책상 불가 | 대안 A(절전+예약) 또는 B(상주 감시) 유지 |
| 판단 보류 | 두 방식 병행 운용 가능함. 단, **중복 전송을 막기 위해 감시 폴더를 분리**해야 함 |
