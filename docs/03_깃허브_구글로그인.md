# GitHub 구글(Google) 로그인 — 가능 여부 및 대안

## 1. 핵심 요약

- **개인 GitHub 계정에는 “Google로 로그인” 기능이 없음.** GitHub은 Google을 개인 계정용 소셜 로그인 공급자로 지원하지 않음
- Gmail 주소를 GitHub 계정 이메일로 등록해도 **로그인 방식은 바뀌지 않음**
- 다만 **패스키(passkey)** 를 쓰면 Google 계정(안드로이드·Chrome의 Google 비밀번호 관리자)에 자격증명이 저장돼, 실사용상 **지문·얼굴 인식 한 번으로 GitHub에 로그인**하게 됨 → 요청 취지에 가장 가까운 방식임
- Google 계정을 진짜 신원공급자(IdP)로 쓰려면 **GitHub Enterprise Cloud + Enterprise Managed Users** 가 필요함. 유료 조직 상품이며 개인 계정에는 적용 불가함

## 2. 대안 비교

| 대안 | 실현 방식 | 모바일 편의성 | 비용 | 판단 |
|---|---|---|---|---|
| **A. 패스키 등록 (권장)** | GitHub → Settings → Password and authentication → Passkeys → Add a passkey. 안드로이드/Chrome이면 Google 비밀번호 관리자에 저장됨 | 높음 — 비밀번호 입력 없이 생체 인증 | 무료 | **채택 권장** |
| B. GitHub Mobile 앱 + 2단계 인증 | 앱에서 1회 로그인 후 세션 유지. 데스크탑 로그인 승인도 앱에서 처리 | 높음 | 무료 | A와 병행 권장 |
| C. Enterprise Managed Users(OIDC/SAML) | Google Workspace를 IdP로 연결 | 높음 | 유료(GHEC) | 조직 단위 도입 시에만 검토 |
| D. Gmail을 계정 이메일로 등록 | 알림·복구용 | 변화 없음 | 무료 | **로그인 방식과 무관 — 요청 해결책 아님** |

## 3. 실행 절차 (대안 A)

1. 모바일 브라우저 또는 PC에서 `github.com` 로그인
2. 우상단 프로필 → **Settings**
3. 좌측 **Password and authentication**
4. **Passkeys** → **Add a passkey**
5. 저장 위치 선택
   - 안드로이드 · Chrome → **Google 비밀번호 관리자** 선택 → 지문·얼굴 인증
   - 아이폰 · Safari → iCloud 키체인
6. 등록 완료 후 로그아웃 → 재로그인으로 동작 확인
7. 2단계 인증 **복구 코드**를 별도 보관함(기기 분실 대비 — 필수)

## 4. 리스크 요소

| 리스크 | 영향 | 대응 |
|---|---|---|
| 패스키 저장 기기·계정 분실 | GitHub 로그인 불가 | 복구 코드 별도 보관, 패스키를 2개 기기에 등록 |
| Google 계정 탈취 | GitHub 계정까지 연쇄 노출 | Google 계정에 2단계 인증 필수 적용 |
| 조직 정책상 개인 소셜 로그인 제한 | 도입 불가 | 대안 C(EMU) 검토 — 별도 예산 필요 |
| 자동화 계정과 혼동 | 중계 자동화가 개인 로그인에 의존하게 됨 | 자동화는 **로그인 세션이 아니라 봇 토큰·PAT**로 동작하도록 유지함(현 구성 그대로) |

## 5. 이번 자동화와의 관계

- 본 중계 자동화는 **GitHub 로그인과 무관하게 동작함**
  - 텔레그램 전송: 봇 토큰 사용
  - 파일 수집: OneDrive/공유 폴더 직접 접근
- 따라서 GitHub 로그인 방식 변경은 **업무보고 미수신 장애와 인과관계가 없음**
- 모바일에서 저장소·로그를 확인하기 위한 **접근 편의 개선 사항**으로 분류함
